# Managing the expiry date of a resource

Beyond the expiry policy your administrator configures, you can flag a password as expired yourself, and choose when a password should expire.

:::important[If you cannot see these menu entries]
Three conditions must be met: your administrator enabled password expiry, they also enabled the "Policy Override" option that allows users to override the default policy, and you have at least the update permission on the resource. Someone with read-only access does not get these entries.
:::

## Mark a password as expired

1. In the passwords workspace, right click the resource.
2. Select **Mark as expired**.

<Figure
  src="/img/help/2026/08/resource-expiry-context-menu.png"
  alt="Mark as expired and Set expiry date in the resource contextual menu"
  caption="fig. Expiry entries in the resource contextual menu"
/>

The entry disappears once the resource is expired, so a resource you cannot flag again is already flagged.

The other owners of the resource are notified by email, with a subject such as "Ada Lovelace marked the password Bitwarden as expired". You are not notified of your own action. On a resource that uses encrypted metadata, the name cannot appear in the subject, which then reads "Ada Lovelace marked a password as expired".

## Set or remove an expiry date

1. Right click the resource, or select it and use the **more** button of the workspace.
2. Select **Set expiry date**. The dialog that opens is titled "Set an expiry date", or "Set expiry dates" when you selected several resources.
3. Choose one of the three options:
   - **Set the date automatically:** and a number of **days from now**, between 1 and 365.
   - **Set the date manually:** and pick a date in the calendar.
   - **Not set**, which removes the expiry date, described in the dialog as "This resource does not need an expiry date."
4. Click **Save**.

<Figure
  src="/img/help/2026/08/set-expiry-date-dialog.png"
  alt="The Set an expiry date dialog with its three options"
  caption="fig. The Set an expiry date dialog"
/>

You can select several resources before opening the dialog to give them all the same expiry date in one go.

:::tip[Undoing an expiry]
**Not set** is how you cancel an expiry you flagged by mistake, and it stays available on a resource that is already expired. Updating the password also lifts the expiry, when your administrator left the automatic update behaviour on.
:::

## Finding expired passwords

When password expiry is enabled, the resource list gains an **Expiry** column. It shows a relative date, "3 days ago" for a password that has expired and "in 2 months" for one that has not, with the exact date in the tooltip. The cell stays empty for a resource without an expiry date, and there is no separate badge, so the date in the past is the signal to look for.

To list them all, use the **Expired** filter of the workspace. When nothing has expired, it reads "No passwords have expired yet."
